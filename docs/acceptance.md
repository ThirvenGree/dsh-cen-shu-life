模型表现无法由规则保证每次完全一致。当前规则和本地故障恢复测试通过，真实生成对照如上；余额补充后已完成烦躁事件补测与原 QQ 会话动态上下文验收；全程使用原 DeepSeek 路由。

## 生活事件进入原心情判断（1.2）

本机实际安装的 feiyu-mood 0.7.6 已接入：原轮末判断接收未处理的生活记录，对话与生活贡献分开，原插件自行原子保存真实数值、历史及事件回执。生活插件不直接改写心情文件。

受控集成检查使用原插件真实的挂载、判断回调、applyDelta、saveState、normState 和重置流程；仅模型输出使用确定性夹具。验证两轮对话只有两次判断调用，同一事件仅第一轮产生数值变化，总心情70→71、开心0→6，下一次生活上下文采用有点高兴；重置保留去重信息，不重放旧事件。

另一次独立模型验收实际调用当前 DeepSeek，经原 feiyu-mood 的判断与数值应用函数更新内存模拟状态，再把结果交给生活插件生成模式，最后由正常 DSH 会话生成回复。测试没有写真实心情或发 QQ。模拟初始数值用于对比不同背景，不代表一个随机事件能把心情从高兴突然变成低落。

| 原插件模拟心情 | 生活模块模式 | 同一输入“我今天去吃火锅了”的实际回复 |
|---|---|---|
| 70 → 71 | pleased | 哪家！我也想吃，你们点的什么锅底 |
| 90 → 91 | excited | 火锅！！哪家啊，点的什么锅底？这个点去吃，是不是有人请客 |
| 45 → 46 | low | 嗯，吃了什么锅底 |

复测过程中发现低落规则被常态篇幅冲淡、记忆注入可能覆盖当前对话记录，已调整当前模式的优先级并过滤机器来源，保留真正的新消息焦点。最后的低落样例明显缩短，高兴样例增加感叹和主动性。仍不把一次模型输出当作永远一致的保证。

当前自动化：生活模块46项全部通过；原心情插件QQ/延迟判断/衰减29项通过；共享主动策略9项通过；原生心情保存与去重集成检查通过。还覆盖概率0/强度0、稳定抽样、每日候选上限、事件过期、伪造ID、低可信结果、重置防重放。实际心疼/担心、甜蜜和吃醋会同时结合原心情的可信理由及当前语境来改变行为，不能只凭高分猜恋爱或困难。

模型联动事件的输出预算调整为2400（原普通判断仍1000），避免推理耗尽1000后没有JSON；仍是一次判断，不额外重试同一事件。无聊天时事件照常推进，真实数值在下一次正常轮末判断更新。


## 1.3：语义判断、升级与内容更新

- 默认数据采用三方合并：未修改的默认字段随版本更新，手动改动和删除保留；首次启动不再永久冻结默认值。
- `GET /state` 仅预览，不推进事件、抽随机数或写入状态。事件推进由定时器与实际会话执行。
- 心情联动采用协议 2 和源码摘要校验。升级覆盖适配会在设置页显示故障；修复按钮可重新安装已支持适配，随后重启 DSH。不兼容的新版本会明确报错，不能保证任意未来版本自动兼容。
- Google `gemini-3.8-flash` 输出固定结构的情境标记，判断表白、需要照顾、恢复等语义；不再解析自由文本 reason。默认从本地环境变量 `GEMINI_API_KEY` 读取凭据，不写入插件配置。支持本机 HTTP 代理、会话隔离缓存、超时与可见降级。原心情插件仍是心情数值的唯一写入者。
- 默认每 24 小时更新生活事件、日程倾向与心情表达细节。生成数据经过类型和范围校验，单独保存在 `model-content.json`，不修改程序代码、人设原稿或手动规则。失败保留上次有效内容，6 小时后重试；生成层 7 天过期。设置页可关闭或手动刷新。
- 内容请求只携带人物与行为配置、已有模板名称，不携带 QQ 聊天记录。语义分类仅发送当前消息正文。调用使用已有 Google 账户额度。

验证：`npm ci`、`npm test`、`npm run check`；原生联动检查 `node scripts/check-installed-mood.mjs <心情插件目录>`。真实模型回归（需要本地 key）：`node scripts/check-google-situation.mjs [本机代理地址]`。


1.4 回归覆盖：周末早晚、七类假期与补班、工作事件禁入假期；事件反应跨阶段和重启固定、配额耗尽不强制烦；未知分类不写可信状态、旧格式拒收、模式即时纠正；熔断恢复与异步 key 缓存；阻止 DNS 重绑定及缺令牌修改；低置信度/未采纳事件消费；组装等待一次分类并只计算一次上下文。
