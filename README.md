# dsh-cen-shu-life

岑舒的独立生活插件。按《岑舒_第七版》维护日程、轻量随机事件与心情行为，不修改 DSH 核心，不自己发送消息。

## 安装

需要 Node 22+ 和 DSH Desktop。当前实测 DSH 0.2.1-rc.3、dsh-feiyu-mood 0.7.6、dsh-speak-up 0.2.6。

```powershell
git clone https://github.com/ThirvenGree/dsh-cen-shu-life.git
cd dsh-cen-shu-life
node scripts/install.mjs "你的DSH家目录/profiles/desktop" "你的岑舒会话ID"
```

重启 DSH。设置侧栏打开「岑舒生活」，设置目标会话与心情记录键。修改设置立即生效；安装、更新宿主代码需重启。默认不绑定任何会话，其他角色不受影响。`DSH_HOME` 优先，否则使用用户家目录下 `.dsh`。

## 职责

- `dsh-feiyu-mood`：判断、保存和衰减心情。
- `dsh-speak-up` / 现有 QQ bridge：继续各自触发主动聊天。
- 本插件：日程、事件、行为映射、上下文，不调用模型做心情判断、不直接发送。

实际安装版本的 `/dsh-feiyu-mood/state` 调用会执行 `getState(... persist:true)`，不是无副作用的跨插件读取。因此采用只读 v2 文件适配器；验证版本、七维数值与明确会话绑定，读取失败保持平常并记日志。文件更新异常不会写回原心情。不读取或覆盖整份聊天历史。

## 插件内设定与工具联动（1.1）

人物背景、一般说话方式、关系边界、每周倾向及工具协作规则保存在本地 `profile.json`；11 种模式的表达规则保存在 `config.json.modeRules`。首次使用的默认规则来自 `data/behaviors.json`，不是测试消息中的长提示词。DSH 设置 → 岑舒生活，可在现代化面板中直接编辑并保存，下一轮立即读取。原始角色卡保持只读。

`censhu_life_context` 是绑定角色专用的状态读取工具；每轮也通过动态上下文自动读取，不依赖模型记得调用。工具仍按已有配置工作：BrowserSkill 路由、文件/图片/表情预览、语音、生图和记忆不会被生活模式禁用。心情只调表达，明确任务仍需完整完成。API 密钥仍在原环境变量中，不复制到本插件。

测试会话通过 `/simulate/session` 临时挂载隔离的模拟上下文，聊天里只传真实测试发言，不贴整段角色设定。模拟绑定只存内存，20 分钟过期，禁止覆盖正式角色会话，可主动清除。

## 生活事件 → 真实心情（1.2）

本机已安装原心情插件适配。重新安装到兼容部署时运行：

```sh
node scripts/install-mood-link.mjs /path/to/dsh-feiyu-mood
```

安装器针对本部署已适配的 feiyu-mood 0.7.6 检查源码锚点、保留备份，再接入原有轮末判断。未知版本会在写入前拒绝；不修改 DSH 核心，不手动改原心情文件。

事件开始、阶段推进和自然结束时，从 `mood-reactions.json` 按人物兴趣与事件类型抽取一次轻微反应，保存在 `mood-events.json`。默认 65% 进入加权反应抽样，抽样里仍包含平常反应；强度 1，每天最多 4 个候选，24 小时过期。同一候选刷新、重启不重抽；概率/强度只影响以后产生的候选，关闭联动会暂停所有待处理输入。

原 feiyu-mood 下一次正常轮末判断同时处理新对话与未处理事件，仍只调用一次判断模型；把生活贡献单独列出，允许为 0。每次生活原始贡献限制为总心情 -3..3、单维 -6..6，并沿用原心情总分缓慢变化机制。生活事件不能生成甜蜜、吃醋、心疼或担心青枔等关系情绪。采样为中性时数值贡献强制为 0。

原心情插件自己保存数值、历史和事件回执；生活插件仅重读。重复事件、过期事件、重置前事件不会再次加分，也不允许因角色复述事件或旧心情造成的口吻持续自增。事件发生时没有聊天，不单独唤醒模型；等下一次正常判断更新真实数值。

新心情会在下一次符合条件的请求转成当前表达模式。当前模式优先于常态篇幅：低落不会因为普通设定写着三五句而继续连问。青枔明确需要关心、认真问感情等情境优先，明确任务和工具执行不因心情被省略。

设置页面新增生活情绪开关、反应概率、强度、每日上限、有效期和待处理状态。独立的模型联动模拟调用原心情插件的判断与数值应用函数，但只更新内存模拟对象，不写真实心情，不发 QQ。

```sh
node scripts/check-installed-mood.mjs /path/to/dsh-feiyu-mood
```

这是可选本机集成检查，不参与无外部插件的 CI。适配源码备份为 `lib/index.js.before-life-link.bak`；解除适配时先关闭生活情绪开关，在确认心情插件未另行升级后恢复该备份。保留原心情数据与角色卡。

## 功能

- 上海时区日程，可修改；工作日与周末分开，春节按农历判断。
- 17 个 JSON 事件模板：档案工作、旧书、纪录片、整理、感冒、修路、家庭电话、天气、季节、工资及出行。每个模板含条件、权重、阶段、持续时间、冷却与重复限制。
- 默认每 30 分钟一次随机检查，概率 0.22，每日最多 2 件、同时最多 2 件；可以没有新事。离线不补造大量事件，重启只推进已存在事件。
- 天气必须手动确认有效期；工资日未配置不触发；出行默认关闭。不会自动查询现实天气、工资或出行。
- 11 种行为：平常、有点高兴、很高兴、低落、心软、难为情、吃醋后收声、累、烦、被惹到、慌。综合可信心情、基线差、七维变化、日程与真实新消息；低分不等于烦，甜蜜不自动等于难为情。
- 关心优先、感情场景优先、最短维持、恢复过渡与最长有效期。阈值、持续时间、各模式具体规则可配置。
- 每轮重新读取有效心情，使用 DSH `systemPrompt.context`，只注入绑定会话。心情判断在轮末完成，下一次模型请求使用新结果，不回写已生成回复。
- QQ 初始快照及等消息工具返回的新消息参与场景判断；成功发送及 DSH 正文参与提及记录，避免连轮重复。
- 设置页支持开关、绑定、时区、数量、概率、分类、阈值、行为文本、状态预览、手动新增/结束/重置、完全隔离的模拟测试。

事件属于角色生活模拟，不是用户现实经历。日程只是倾向；未记录的书名、影片结局、电话细节不当事实。事实约束不能保证模型每次生成都完全遵守，因此提供实际回复验收与样例。

## 本地文件

`<DSH_HOME>/cen-shu-life/` 下保存 `config.json`、`profile.json`、`events.json`、`state.json`、`history.json`、`diag.log`。JSON 均有版本号，原子替换；损坏配置保留备份，恢复默认且不自动绑定。日志有大小上限，历史有数量上限。原始人物卡和心情文件始终只读。

`modeRules` 为模式键到行为文字的 JSON 映射（如 `{"low":"回复变短……"}`），空对象使用默认规则。天气只使用联网查询并保留搜索来源的大理当日预报；手动 `weather` 配置已移除，旧配置会自动清理。

## 接口

接口挂载在同一 DSH 本地回环服务。实测当前版本的插件路由可在本机直接访问，不要求 DSH 会话 Cookie；修改接口检查同源，返回内容不包含密钥或聊天令牌。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/dsh-cen-shu-life/settings` | 独立设置页面 |
| GET | `/dsh-cen-shu-life/state` | 状态、心情读取结果、上下文与模板 |
| GET/POST | `/dsh-cen-shu-life/config` | 读取/保存设置 |
| GET/POST | `/dsh-cen-shu-life/profile` | 读取/保存人物与工具联动设定 |
| POST | `/dsh-cen-shu-life/simulate/session` | 独立测试会话的临时模拟绑定/清除 |
| POST | `/dsh-cen-shu-life/event` | `{action:"add",templateId}`、`{action:"end",id}`、`{action:"reset"}` |
| POST | `/dsh-cen-shu-life/simulate` | 独立心情、场景、日程与事件模拟，不修改真实状态 |
| POST | `/dsh-cen-shu-life/simulate/judge` | 调用原心情判断处理模拟事件，返回模拟数值和后续模式 |

卸载时从 profile 的 dependencies、bundles 移除本插件并重启；自己的数据可保留，永不删除原始角色卡或心情数据。恢复安装可复用旧事件。

## 1.3：语义判断、升级与内容更新

- 默认数据采用三方合并：未修改的默认字段随版本更新，手动改动和删除保留；首次启动不再永久冻结默认值。
- `GET /state` 仅预览，不推进事件、抽随机数或写入状态。事件推进由定时器与实际会话执行。
- 心情联动采用协议 2 和源码摘要校验。升级覆盖适配会在设置页显示故障；修复按钮可重新安装已支持适配，随后重启 DSH。不兼容的新版本会明确报错，不能保证任意未来版本自动兼容。
- Google `gemini-3.8-flash` 输出固定结构的情境标记，判断表白、需要照顾、恢复等语义；不再解析自由文本 reason。默认从本地环境变量 `GEMINI_API_KEY` 读取凭据，不写入插件配置。支持本机 HTTP 代理、会话隔离缓存、超时与可见降级。原心情插件仍是心情数值的唯一写入者。
- 默认每 24 小时更新生活事件、日程倾向与心情表达细节。生成数据经过类型和范围校验，单独保存在 `model-content.json`，不修改程序代码、人设原稿或手动规则。失败保留上次有效内容，6 小时后重试；生成层 7 天过期。设置页可关闭或手动刷新。
- 内容请求只携带人物与行为配置、已有模板名称，不携带 QQ 聊天记录。语义分类仅发送当前消息正文。调用使用已有 Google 账户额度。

验证：`npm ci`、`npm test`、`npm run check`；原生联动检查 `node scripts/check-installed-mood.mjs <心情插件目录>`。真实模型回归（需要本地 key）：`node scripts/check-google-situation.mjs [本机代理地址]`。


## 1.4：日历、可信情境与请求边界

2026 年日程按官方放假与调休日期区分工作、休息、早晚活动。工作事件使用同一工作日判定。日历来源：[国务院办公厅通知](https://www.gov.cn/zhengce/content/202511/content_7047090.htm)。未覆盖年份仅提供基础节日识别，不声称知道尚未收录的完整调休安排。

每条消息在收到时发起一次 Gemini 分类，生成回复及读取上下文工具等待同一任务；上下文只在组装时计算一次，读取不推进事件或写盘。失败、超时和低于 70 的结果均为未知，不使用正则制造可信状态。连续失败三次熔断一分钟；key 优先读取进程环境，注册表查询为异步并缓存五分钟。

协议 3 要求情境携带模型来源与时间。1.4.1 起，分类中、未知和普通回应保留仍有效的旧证据；只有可信且明确的恢复/撤回标记会立即解除对应模式。事件反应在开始时固定，各阶段不重抽；配额与心情联动开关只控制提交，不改变该事件自身的抽样与行为。原心情插件成功处理一批事件后即记已处理，即使低置信度、未采纳或零变化，也不反复提交。请求失败未得到判断时仍可重试。

所有设置路由校验本机 Host、端口、来源与连接地址。修改请求还需先从受保护的 `GET /state` 获取本进程 `csrfToken`，以 `x-censhu-csrf` 请求头发送；昂贵操作有十秒限频。Token 不写入配置或 URL，DSH 本身的会话鉴权继续生效。


## 1.4.1：跨回合情境连续性

“本句没有提到难受”不等于“已经恢复”。待分类、未知、关闭语义辅助、普通回应或回合结束，不撤销可信旧证据，也不跳过最短维持和恢复阶段。`behaviorContext` 的需要关心、撩拨、第三方感情证据重新参与心情行为联动。`soft` 仅被明确且可信的 `careResolved` 立即解除；Gemini 同时参考上一份有效情境与此前模式；其他情境型模式使用模型输出的 `resolvedModes` 标注明确撤回/澄清，普通的“嗯”“好”和话题切换不构成解除。

每项正向证据、每项解除标记都有独立时间戳；普通回应不续期旧证据。证据自然过期后采用原有维持与恢复逻辑。未知结果不会写成可信情境，也不会覆盖最后有效情境。事件自身反应始终独立抽样、跨阶段固定；`moodLinked` / `lifeMoodEnabled` 关闭时，“烦”等行为依然可触发，只是不提交心情影响。


## 1.5：开放、动态的主观判断

Gemini 参考人物摘要、既有可信情境、先前开放判断、心情维度与已发生的生活事件，输出自由命名的感受、理解、说话倾向和行为建议。开放标签不受 11 种基础模式限制，允许混合感受、不确定和困惑。基础模式继续执行已配置的关心优先、最短维持与恢复规则；开放判断在这些底线内细化表达。

判断采用 preserve/update/resolve 三种内部操作协议控制延续，情绪名称和表达内容由模型生成。不确定的模型结果可以作为未定性的表达背景保留，但不能解除旧关心、制造表白证据或改写心情数值；网络错误不扮作角色困惑。当前开放判断会保存在本地、在“模拟与预览”中展示，并随有效期过期。模型仍只更新内容与建议，不修改程序、权限、人物核心或直接执行发送。


## 1.5.1：缓存、情境寿命与人物口吻边界

`semanticCacheMinutes` 仅决定 Google 分类 API 结果的复用时长（默认 15 分钟）。独立的 `situationValidityMinutes` 决定情境证据、解除标记和开放判断的寿命及 preserve 窗口（默认 120 分钟，1–1440 可调）。普通回应不续期各项旧证据，原有最短维持、恢复过渡仍独立执行。

Gemini 关闭、不可用、超时或熔断时，仅启用整句明确困难的关心兜底，例如“今天好难受”。兜底来源单独标记、置信度不补高，不持久化成可信模型证据；不会推断表白、冒犯或恋爱。“我已经不难受了”“我朋友今天好累”和引用台词不触发。

开放判断自由文本、每日内容层中的日程备注及口吻/行为建议仅保存并展示，不再注入角色系统提示，也不回传给下一轮分类。分类只接收之前的结构化情境和确定程度；主聊天模型依据原人设自行选择语气；生成的生活事件仍作为经过校验的候选，在真正开始后进入生活记录。模型产生的动态标签仍可在设置页查看，不确定/困惑通过受控的状态提示保留。先前 1.5 关于开放文本影响表达的描述由本节替代。


## 1.6：模型建议时长与临时内容注入

情境按类型分别计时。Gemini 通过 `durationMinutes` 建议各项保留时间；程序将建议限制在设置的类型上限与总上限内。默认关心/恢复标记上限 120 分钟，撩拨、第三方感情、表白 20 分钟，冒犯 30 分钟；旧记录没有时长时采用这些类型默认值。每项保存独立起点和到期时间，普通回应不能续期。短期难为情/吃醋/慌的维持与恢复各最多 5 分钟，避免情境到期后再额外恢复半小时；心情维度仍决定有效情境能否触发。

按用户最新要求，恢复开放判断四项自由文本（感受、理解、说话方式、行为建议）注入，每项最多 200 字。`assessmentMinutes` 由模型建议、总上限约束；记录固定到期时间，preserve 不续期。人物核心、手动规则、明确任务和工具权限始终优先。此节替代 1.5.1 的“仅展示”策略。

每日更新的日程备注与行为建议通过每条 `validMinutes` 提出时长，按日程时段和当前模式筛选后作为临时内容注入。日程备注可从当天对应时段开始计时；所有备注最迟在本批生成后 24 小时内退出。候选生活事件仍有独立的七天候选有效期。到期不会改写人物原稿。


## 1.6.1：未来时段与首次模式激活

日程备注按配置时区定位生成后 24 小时内对应时段的下一次出现；已过时段安排到次日。正在该时段内则从生成时刻起计时，开始前则从该时段开始，结束不超过时段末尾及整批截止。秒数不会把窗口错移到下一分钟，跨日和跨年也按当地日期处理。

行为备注生成后处于待用状态，在后台或聊天正式评估首次提交匹配模式时开始计算模型建议时长。离开再回到该模式不会续期，激活时刻和到期时间持久化，重启也不续期。状态读取、上下文预览均不激活或写盘。所有备注最多保留到该批生成后 24 小时；临近截止才触发也只获得剩余时间。

旧的仍有效批次会迁移到新时段规则：使用原始生成时刻和原批次截止重算，不从升级时刻重新获得 24 小时。尚无首次模式激活记录的旧行为备注转换为待用；新格式后续重启不再重置。候选事件与四项开放自由文本的有效期机制保持原样。


## 1.7：大理每日联网天气与主动机会

地点固定为云南省大理白族自治州大理市。默认北京时间每日 07:00 后查询一次；程序晚启动则当日补查，需 DSH 运行。使用现有 Gemini 模型、环境变量 key 和代理，先调用 Google Search 获取搜索证据，再结构化提取预报。拒绝没有真实搜索来源、地点/日期不符或非法温度的结果，不以月均气候替代当日预报。设置页显示来源、查询时间并支持手动刷新。预报在大理当地午夜过期；失败保留仍有效的上次结果，一小时后重试。搜索与提取会使用 Google 搜索/API 额度。参考：[Google Search Grounding](https://ai.google.dev/gemini-api/docs/generate-content/google-search)。

天气预报作为临时背景进入人物上下文，可温和影响表达。每天最多一条天气心情候选，建议总分不超过 ±3、happy/calm/sad 不超过 ±4，由原心情插件现有的后台生活判断路径采纳与写入，无需等待聊天回合。天气候选有独立每日一次额度，日常小事配额不受占用。

运行 `node scripts/install-weather-policy.mjs <dsh-censhu-policy目录>` 接入 bridge 与 dsh-speak-up 的共享主动策略。两套现有主动检查都可考虑天气话题，未处理的当日天气机会给予温和概率修正；仍保留原时段/心情/概率门槛、60分钟共享冷却与互斥锁，同日天气机会共享去重。机会被处理不等于消息已发送，模型仍可选择不说；也不会强制两套同时发送。四个天气开关及查询小时可在设置页修改。


## 1.7.1：天气独立额度与主动策略健康检测

日常候选额度统计排除具有完整天气标识的候选。天气仍在同一心情队列中，每天最多一条；默认可同时有天气一条及日常小事四条，共五条。每轮仍最多取两条，后续正常心情判断继续消费余下候选，不必增加单轮模型负担；模型仍可判断为零变化。天气先到、后到、日常额度已满或为零都不占用日常额度。

天气主动辅助层增加协议 1、源码 SHA-256、目标包及依赖校验，安装记录写在本地 `weather-policy-install.json`。检测到重装、适配缺失或摘要改变时，天气概率修正和主动话题暂停，普通主动策略及天气查询/心情功能不因此关闭。设置页显示单独故障横幅；兼容版本可点击“检查并重新接入天气主动策略”，成功后需重启 DSH 与 bridge。修复接口使用既有本机 Host/来源/CSRF 校验及限频。未知不兼容源码明确报错，不保证任意未来版本均可自动修复。


### 1.8 动态内容与已有记忆联动

- 模型依据人设、当前时间/季节、心情、天气预报、近期事件和指定 DSH 记忆生成候选事件与情绪反应。每批最多12个，不要求凑数；滚动事件池最多80条，各自7天到期，重复不续命。内置模板继续作为基础。
- 事件附带模型生成的轻微反应供随机采样；同一事件只抽一次，阶段不重抽。关闭心情数值联动仍保留行为反应；原心情插件继续独占数值写入。
- 每轮开放判断、每日临时表达与手动模式倾向共同参考，允许主模型自然选择、混合或不用，不是固定台词。
- `personaMemoryFiles` 选择 DSH `memories/` 下的相对 Markdown 文件，接入已安装记忆插件维护的项目 MEMORY.md、KEY.md 等。只读选定文件，不扫描其他项目、不修改记忆插件，也不写 Codex 记忆。当前模型仅提炼提及岑舒/青枔的记忆段落。
- 人物更新存于 profile.json 的 evolvingFacts：经历、偏好、关系细节，必须引用本批真实记忆证据且置信度至少90；模型决定1至90天有效期，相同内容不自动续期。不确定时不写事实。人物核心、边界、权限与手动规则优先，模型无法改写这些字段。
- 仍由原有记忆功能记录与整理对话；生活插件读取其结果。每分钟检查选定记忆，变化距上次成功生成满1小时后可提前刷新；失败仍退避6小时。设置页可关闭联动、编辑/清空人物补充，自动更新保留最近10次人物修订于 persona-history.json。
- 生活总览增加大理当日天气卡片，展示有效预报、温度、日期和更新时间；到期不展示昨日天气，来源在模拟与预览页。

已安装的 dsh-memory-evolve（memory:snapshot）、Mnemon、OpenViking 在绑定会话提供的命名记忆上下文也会自动接入，按会话隔离、7天上限，原插件继续负责召回和存储。只读取命名记忆上下文里涉及角色/青枔的短段落，不把整段普通用户提示当记忆。

`censhu_memory_review` 向所有 DSH 会话提供 Gemini 记忆质量审核工具：保留、压缩、待核实、过滤，逐条返回原始 id 和理由。审核本身不改存储；主 DSH 使用其已有 memory、Mnemon、OpenViking 等工具执行写回和归档，因此仍保留原插件的来源、范围和恢复机制。

生活总览展示鱼的心情的总值和7个维度、最近生活贡献与本轮实际变化（包含同轮对话贡献，不误标为纯生活贡献）。生活候选经原插件正常回合统一判断、去重、写入其真实state；允许判定无变化，不伪造涨跌。反向读取原插件数值决定当前模式/表达，内容生成也携带数值；显著变化且距上次成功生成满1小时可提前刷新内容，不每次读页面调用模型。

### 1.8.1 内容容错、证据留存与双向反馈

- 每日内容逐个校验事件、日程、表达和人物补充；不合格单项及重复项丢弃，合法同批内容照常采用。设置页显示采纳/过滤数量；不支持的根版本、网络失败仍保留上一份内容。
- 人物补充保存证据原文、来源、原始有效期；本次没召回、召回截断、来源暂时不可用不删除补充。新内容不能挤掉有效旧补充。旧格式在再次召回相同证据时补存原文，未补齐时仍保留到原有效期。明确成功的原记忆 remove 操作撤销匹配证据；多个独立证据仍有效时保留补充。Gemini 可根据当前明确否定证据提出 factRevocations，须引用当前有效证据且置信度至少90，撤销与到期不同于召回缺失。
- 生活总览数值与鱼的心情一致取整展示，底层数值精度保留；中文显示各维变化，区分生活判定量与同轮实际变化（含对话且经过原心情插件折算）。
- 原心情时间线保存生活事件名、判定量、实际变化。鱼的心情设置及挂件增加「受到的影响 / 产生的影响」列；生活总览也有这两列，展示真实队列、判断记录和读取确认。候选未判断不会显示成已生效，行为反馈不等于发过消息。
- 生活插件每3秒检查数值修订，变化后重新评估行为并保存读取确认；普通页面读取仍无副作用。模型事件池、临时心情表达及显著变化触发内容刷新继续运行，页面标示模型动态内容和下次更新时间。
- `install-mood-link.mjs` 同时安装原心情接口及两个展示入口的反馈适配；可重复运行，原生文件先备份。

### 1.8.2 记忆条目边界与动态表达状态

记忆文件及已安装插件的记忆上下文共用条目解析：支持不空行的 Markdown 列表、编号列表、带日期条目、§分隔以及缩进续行；超长单条拆成不超过1200字的片段，各片段记录共同的原条目标识。证据ID不依赖相邻条目与列表编号。删除仅按完整条目标识/规范化全文匹配，不再用子串使整段失效；旧版整段引用不因删除其中一条就被全部撤销。旧格式缺少精确条目归属时保留到原有效期或交给有新证据的模型复核，不猜测其所属。

「心情与表达」页直接显示模型动态表达开关、最近生成/下次检查时间、未到期的每日表达建议及等待/当前有效状态、本轮开放判断；基础模式仍可编辑，模型表达不是固定台词。

### 1.9 每4小时的 Gemini 随机生活事件

首次安装后默认4小时第一次，之后每4小时一次；重启沿用保存的下次时间，错过多个时段只补一件，不集中补发。`timedEventsEnabled` 可开关，`timedEventHours` 默认4，可在设置调整。生活事件页显示下一次发生、最近事件和失败原因。网络/校验失败15分钟后重试，禁用或卸载后的迟到结果不提交。

Gemini 结合人物、时间/休假、当前心情、天气预报、记忆和近期事件，加随机盐动态创作一件普通生活小事，并在同一次调用给出轻微情绪判断和自由表达倾向。事件独立于日常概率抽选及其每日配额，保留一个定时事件名额；单件持续15–180分钟，不因原有每日上限被丢掉。仍不冒充用户经历，不新增未确认的外部事实。

事件及Gemini情绪结果入持久队列，原鱼的心情在自身串行写入队列中每3秒检查，不需要对话回合，也不再调用第二个模型。数值由原插件应用折算/上下限并保存到原state，生活贡献仍限制总值±3、开心/踏实/难过各±6，允许部分或全部不变；不强制造成恋爱维度。普通对话路径不再重复处理定时条目，重启未消费条目可继续消费，重置/禁用/改绑闸门保持有效。阶段结束不重复入队，同一记录只处理一次。

共享岑舒心情经现有联动影响生活行为、临时表达和两套主动聊天的判断。随机事件本身不发消息、不绕过作息或共享冷却。

### 1.9.1 最近证据优先与持久计时

文件记忆从新到旧选择：带明确日期的条目按日期降序，其余按文件末尾优先；跨文件先比较日期，再比较文件更新时间。证据ID仍与读取排序无关。文件独享最多32条/8000字，运行时召回独享最多16条/4000字，二者互不挤占；撤销及重复证据在选取前过滤。

重启保留原bootAt、nextAt及失败重试截止。未来的截止不延后；已错过的截止在启动后检查时只触发一次，随后跳至原节奏的下一个未来时段，不逐个追补。只有无有效存档时从当前时间加4小时开始，关闭期间不调用模型，重新开启仍按已有截止处理。

### 1.9.2 每个记忆文件保底

文件证据先按来源分组，每个有有效证据的文件先取最多3条（各自仍按日期/末尾优先，并受公平分配的字数约束），再把32条总名额中的剩余名额按全局新旧补齐。文件缺失、全被撤销或不足保底时不占空名额。通常字数预算仍为8000；为保证最多8个文件各自至少能容纳一条最长1200字证据，必要时上限扩至9600字。运行时召回仍使用独立16条/4000字。KEY.md 不再因其他文件拥有大量带日期的条目而完全不可见。

### 1.10 Gemini 语义选择记忆

生活内容及4小时事件生成前，Gemini 会对指定文件的全部安全候选条目进行分批评估；不再先取保底窗口再交给模型。评分综合当前话题、人物、心情、作息/事件、长期关键事实与时效，KEY.md 名称、日期和文件位置均非硬性优先级。选取保留原始证据ID、原文与来源，不生成替代事实；文件选最多32条/9600字、运行时召回16条/4000字，KEY可以超过3条，也可选择文件开头的重要事实。显式姓名不再是指定文件候选的必需条件，由模型判断适用性；仍仅读取选定的DSH记忆文件，不扫描其他项目。

每批最多48条/20000字，遍历所有安全候选并使用一致的0至100分标尺；多批分数汇总后择优。模型评估属于近似语义判断，不保证每次排序相同。相同上下文/证据15分钟复用评分，新候选单独评估，同引擎并发请求合并。模型失败或输出不完整时显示degraded并退回按文件保底读取，5分钟退避；不把保底结果标成模型选择。页面显示候选/选中数及各来源数量。未选中证据不会因此删除已验证的人物补充。

### 1.10.1 长期重要性与话题相关性分层

长期重要性按条目保存7天，仅核心人物背景/边界或评分模型变化时重建；不包含最近消息、当前心情、作息和自动补充。内容变更产生新证据ID，仅新增/过期条目需重新评估。新话题在重要性候选池中单独重排最多48条，保留高重要性主集及随情境轮换的探索条目；有运行时召回时文件/召回候选分别最多32/16。相关性评分按情境和候选池缓存15分钟，保留最近4个情境。旧版混合评分首次升级时重建一次，不误用为长期评分。

每个成功批次的评分独立保留。重要性批次失败，只为该批条目设置5分钟退避；未评分条目可使用提及岑舒/青枔的保底结果填余量，也可因成功模型结果已满而暂不入选。其他成功批次仍正常采用，退避结束只补失败条目。话题重排批次失败则仅该批沿用长期重要性，不回滚成功批次。页面显示长期评分复用数和两层各自调用批数，degraded表示部分结果降级。任何保底路径均恢复人物姓名筛选；宽候选仅供模型判断，不直接当可信证据。以上替代1.10的整库话题缓存及整批回退行为。

### 重要记忆自动写回（1.11）

绑定会话的真实来信进入独立审核队列，由已配置 Gemini 提炼稳定事实、偏好和明确决定。只采用有逐字原话证据、置信度至少 90、重要性达到设置阈值的条目；临时心情、模拟生活、凭据与推测不写入。通过 DSH 原生工具执行链分别调用记忆宫殿 `engram_save`、Memory Evolve 项目轨 `memory`、灵枢 `mdcg_remember`，保留各自的冲突与审核规则。每个后端独立记录已保存、合并、待审核或失败；成功不重复写，失败单独重试，重启保留队列。设置页显示真实结果；未注册的工具显示未就绪。Mnemon/OpenViking 的召回上下文仍进入人物证据联动，远程服务是否可用由原插件配置决定。`POST /memory/review` 可提交绑定会话原话复核（本机认证及 CSRF 保护），不会生成聊天消息。

### 重要记忆审核的调用频率与容错（1.11.2）

| 路径 | 调用时机 | 失败处理 |
|---|---|---|
| 重要记忆写回 | 每条至少4字、通过凭据/诊断过滤的绑定会话真实来信，后台额外调用一次 Gemini；与情境分类独立，同文来信去重 | 网络、超时及服务错误每15分钟重试，不消耗格式次数；仅模型 JSON/顶层结构格式错误累计3次后暂停。次数及退避跨重启保存，可在设置页点击“重试失败项”恢复 |

每次提炼最多32个候选，逐项验证证据与可信度；超过4项不再整批报错。非法单项丢弃，其他合格项照常保存。原记忆工具的保存重试独立进行，不会重新调用 Gemini 提炼已审核成功的来源。当前未合并两条模型路径，符合条件的新来信仍可能分别调用情境判断和重要记忆审核。

1.11.2 将网络故障与格式校验分开计数；只将模型输出 JSON 无法解析、顶层 memories 非数组标为格式错误，HTTP/代理/超时/凭据等服务异常不计入格式次数。旧版耗尽总尝试次数的来源恢复待审核。未审核或失败的原话完整保留，只有已完成来源最多保留最近100条。手动重试仅重新排队绑定会话的失败/退避来源及失败保存后端，保留已保存、合并、待原插件审核的结果；正在审核时阻止重复操作，路由有本机认证、CSRF与频率限制。

### 1.12 写回队列熔断与生活数值同步

重要记忆审核连续3次临时故障后暂停整个写回队列（包括新来信），首次暂停15分钟，探测仍失败则依次延长为1小时、6小时，此后保持6小时。暂停与级别跨重启保存；到期仅探测最早待审来源，成功后恢复处理后续队列。HTTP 429、5xx、超时/断网使用此退避；其余4xx（含400/401/403/404）、缺失凭据及无效本机代理配置立即暂停并提示检查配置，手动“重试失败项”恢复。格式错误仍单项累计3次暂停。待审核及失败来源共最多500条，满时保留已有队列、拒收新条目，页面累计显示未接纳数量；已完成来源另留最近100条。

普通生活和天气候选不再必须等待聊天回合：原心情插件每3秒检查并通过原有判断模型及串行保存队列处理至多2条；失败15分钟后重试，与聊天及4小时事件共享回执去重。背景判断只应用生活贡献，不产生青枔发言或发送消息。这条路径会额外使用原心情判断模型额度。模型允许判零；非零生活总分贡献在既有±3范围内直接应用，不再被对话的三分之一取整吞掉，七维仍保持原有限幅。悬浮面板采用后端同一人物行为标签，“烦”的图示也同步；总分与当前行为是两个相关但不同的状态，不要求一个标签对应固定分数。无变化的独立生活判断也会刷新显示理由，不沿用过时的聊天理由。

### 1.13 统一细化表情

保留原蓝紫发鲨鱼帽软绘风格，新增12张透明表情。共享 `mood-expression` 选择器按明确行为优先、心情分数及情绪维度补充选择。原心情 `/state` 返回 `expression`（id/label/image/version），设置页、挂饰面板和大图、生活总览直接采用该结果；普通角色无特殊行为时按其自己的心情选择，不强加岑舒模式。旧5张图保留作兼容回退，表情仅可视化已有情绪，不反向改写分数或触发消息。安装/修复适配会同时部署图像、后端和前端。素材与提示词见 [EXPRESSION_ART_V2](docs/EXPRESSION_ART_V2.md)。

### 1.14 统一联网天气事件

删除下雨天、回南天等按天气种类分立的模板及手动天气配置，统一为 `weather-forecast`。只有当天大理联网天气预报有效（日期/地点匹配、有搜索来源及查询证据、当地午夜失效）时才符合触发条件。名称和阶段直接采用当日预报摘要及表达建议，晴、多云、雨、雪、雾或混合天气均走同一模板，不添加操作者确认等无关说明。

天气模板和普通事件共用默认每30分钟的概率/权重抽选、每日总上限、同时进行上限和分类开关；另按大理日期每天最多一次，标记跨重启保留。阶段结束时间不越过预报有效期。预报缺失、过期或关闭联网天气时不可新触发。界面仍显示唯一模板，实际标题随有效预报动态变化。

统一天气事件仅描述生活背景与表达倾向，没有随机情绪反应或数值，开始/推进/结束均不入生活心情队列。每日 `weather-daily` 心情候选保持每日一次独立回执，避免同一预报重复计分。升级会清理旧天气模板和待判断队列，结束旧模板的进行中事件并保留历史；当天已发生过旧天气事件时也视为已用当天机会。其余人物、事件和计分记录保留。


### 生活事件的空间后续（1.15）

事件开始、阶段推进和结束会更新同一条持久分享机会。当前会话模型在原有 bridge / speak-up 主动机会或对话中，结合实时生活、天气、心情和空间记录，使用 `qq_qzone` 的 `decision` 选择考虑、暂缓或跳过；可自由决定正文及是否配图。不会每阶段强制发、不额外调用 Gemini 或创建主动消息定时器。

发布时使用 `eventIds` 关联原事件。只有 SnowLuma 回读正文和图片成功后，bridge 才写回发布回执；同一事件不会因后续阶段重新发布。该过程不写心情候选，也不增加任何心情数值。重启保留判断与回执；GET 状态与渲染均无副作用。首次接入不追发已有历史，进行中的事件和后续新事件自动接入；未处理的分享机会最多保留一天，模型可在此窗口内自行决定暂缓时长。

生活总览展示待考虑、暂缓、跳过、已发布及关联说说。依赖带事件联动协议的 QQ bridge 原生 `qq_qzone` 工具；旧 bridge 不会伪造回执。

### 人设来源与功能补充

本机以已启用的全局 `dsh-cosplay` 岑舒角色卡维护完整身份、关系、语气、表达原则和对话示例。生活上下文只注入日程、事件、天气、心情、临时表达、有效记忆补充和功能边界，保留一小段必要的生活背景，移除长篇重复的通用口吻与称呼规则。设置页的背景也供独立 Gemini 判断和内容生成使用；这些独立 API 请求不会自动继承 DSH 的系统提示。

QQ bridge 的岑舒文件仅保留渠道发送与空间发布规则。基础人设在 dsh-cosplay 修改，动态生活和行为在本插件修改，QQ 操作规则在 bridge 修改。普通会话、QQ 预设与 BrowserSkill 工作代理当前均使用 DSH 全局提示组装；浏览器代理仍优先完成浏览器任务。以后新增使用 `complete: true` 的独立提示预设，或关闭 dsh-cosplay 时，需要重新检查人设覆盖范围。


### 设定一致性

心情模式提供语气与行为倾向，不禁止语音、图片、表情或文件，也不省略明确任务所需的信息。实际消息数量与媒介由当前 cosplay、内容和意愿决定。静态日程和角色示例不是已发生事件；当前事实依照有效生活记录。生活模块通过已有记忆后端审核写回真实重要信息，不另建平行的用户事实来源。历史助手输出及已作废限制不能成为新的人格硬边界。

生活日程和主动策略通过 `dsh-cen-shu-life/calendar` 共用节假日、休息日及调休判断；两套主动机制的安静时段仍为北京时间 02:00–06:00。Gemini 负责现有辅助链中的开放判断、临时内容、适宜有效期和记忆审核，允许未知与困惑；时钟、权限、额度与发送验证仍由程序确认。


### 桌宠共享接入

提供进程内 `cenShuLifeShared` 服务，桌宠可按已绑定会话只读取得当前生活/心情上下文与原记忆链的有效证据。快照不推进事件、不触发另一条会话，也不把完整私密正文暴露到桌宠状态接口。真实桌宠输入可通过 `observe` 进入现有 Gemini 重要记忆审核与写回队列；助手回复、碎碎念与截图不会作为真实用户事实入队。停用生活上下文或改绑后，后续读取立即拒绝旧绑定。


## 1.16 · 画画灵感与 Gemini 媒介判断

生活事件库新增「画画灵感」。它通过普通事件随机抽取和 Gemini 自发判断两条路径产生：Gemini 结合人设、当前对话焦点、生活、天气、心情和近期分享，决定此刻是否自然出现灵感、具体画面、媒介、是否分享、有效时间和下次考虑时间。普通随机抽取后由 Gemini 细化画面；自发路径分别判断是否产生灵感和是否分享，有灵感但暂缓、不确定是否分享或留给自己时也创建生活事件。只有愿意分享才提供主动机会；暂缓可在同一事件内重新考虑。两条路径共用每日/同时事件上限、模板冷却和去重，异步判断期间抽到同一事件也只记一次。生成后另用模型审核来源叙事，灵感本身作为岑舒角色生活的一部分保留与表达，不机械标成“构想/虚构”；已有角色生活可以作为来源，但不额外补造前置经历，也不把画作冒充实拍或写成青枔现实。自发路径在模型不可用或无法确定是否有灵感时不创建事件；普通抽取已发生的事件保留，等待模型细化，不强行分享。

模型可选文字、语音、表情、已有图片或生图，也可暂缓、跳过、不确定。对话原有语义判断也可在临时表达建议里补充媒介倾向，不增加每条消息的独立媒介分类请求。

Gemini 判为可分享后，bridge 复用现有宿主检查提供一次主动搭话机会，沿用两套机制共享的 60 分钟冷却、02:00–06:00 安静时间、会话忙碌和白名单。没有新建独立发消息定时器，不强制每次事件都发送。此功能需要更新后的本机 qq-bridge 集成 `drawing-opportunity.js` 和 `/api/socialV2/life-inspiration` 协议。

QQ Agent 通过 `qq_life_inspiration` 查看或跳过灵感；生图时向 `qq_generate_image` 传入 eventId，桥接使用 Gemini 已规划的描述，返回真实图片供预览；再调用 `qq_send_generated_image`。生成、发送回执自动写回生活插件，同一事件及阶段不重复生成、发送；语音/表情/文字等其他媒介实际发送后，可携带已存在的本会话 messageId 记录 complete。图片已发出而生活回写失败时明确报告回写错误，不引导重新发送。

生活总览显示最新灵感、媒介、判断理由、暂缓/生成/已分享/失败等状态。读取总览不触发模型请求或写盘。真实私聊记忆仍走现有记忆插件审核；艺术画面与模拟生活不写成青枔的现实经历。

画画灵感的普通抽取、自发判断及分享重评统一在当地时间 06:00–23:00 进行。所有画画判断共用至少 60 分钟的间隔；模型可延长等待时间。判断开始前即持久化下次允许时间，失败和重启也不会绕过下限；每次判断仍包含生成和审核两次模型请求，不等于每小时必定调用。

1.16.3：画画灵感权重降至 1，冷却延长至 72 小时，两条入口共用；升级时按现有事件结束时间补足冷却。同一事件首次判断之外最多再重判 3 次，仍暂缓或不确定则记为留给自己，保留灵感和模型原理由并停止追问。计数持久化，网络或无效输出不消耗有效重判次数；成功决定分享仍可正常发送。设置页显示计数和停止原因。

1.16.4：自发路径以北京时间当天第一条真实 QQ 私聊收发消息为起点，发送必须已有实际 messageId；系统唤醒、工具调用和发送失败不算。仅规划下一次考虑窗口，不立刻生成灵感。Gemini 可在每次判断后继续安排，也可决定当天不再自发考虑；窗口起止与宽度由模型结合当前对话、生活、心情动态决定（距现在至少60分钟、至多1440分钟，宽度至少15分钟），系统在清醒时段与窗口交集内随机取具体毫秒时间并持久化。夜间没有交集时移到次日06:00–08:00内随机时刻，次日真实互动后方可延续尚未到点的安排；已错过则重新规划，不立即补发。当天无互动不启动自发路径；普通事件抽取、已有事件及主动搭话保留。规划失败等待1小时，不因3秒轮询重复请求。每日起点、安排、当天暂停和跨日延续在设置页可见。

1.16.5：QQ 活动数据改为 bridge 主动发布的 ~/.dsh/cen-shu-life/qq-activity-v1.json，不再读取 DSH 内部 session_projcache 或 bridge 私有 social-v2.json。接口包含 contract=qq-bridge/life-activity、version=1、timeUnit、updatedAt、bindings、firstByDay 和 messages；timeUnit 明确声明所有时间戳单位（当前 bridge 发布 ms，读取器也可按显式 s 转换）。bridge 每60秒刷新心跳，并将每天首条真实收发回执独立保留14天，最近消息被截断不丢起点。普通文本回执保留真实消息ID；私聊文件上传成功可用独立 receiptId。源缺失、协议/单位/结构变化、绑定不符和超过3分钟无心跳均在画画设置卡显示，并暂停新的自发判断，区别于“今天没有消息”。需要更新后的本机 QQ bridge；不回退内部缓存猜测数据。OneBot 原始 time 为秒，bridge 的 time/at 为 Date.now() 毫秒，含义是桥接观察或实际发送确认时间。

1.16.6：活动接口中的单条坏消息或每天首条坏记录只跳过该项，不再阻断其他消息和自发判断；设置页显示本次读取跳过的记录数（含首条记录）。单条时间戳异常同样跳过。协议、顶层结构、单位、心跳和会话绑定仍校验，无法可靠读取的数据源会提示并暂停。即使所有记录无效，也只等待后续有效互动，不调用模型。

1.16.7：读取成功但所有记录都无效时（例如 bridge 把秒级时间戳声明为 ms），数据源状态标记为 `all-invalid` 并在设置页显示 ⚠ 与原因，不再显示为“正常”，以免被误认为当天没有聊天。行为不变：仍不调用模型，等待后续有效互动；部分记录无效时仍为 `partial` 并显示跳过数。

1.17.0：为独立感知插件提供 cenShuLifeShared v2 与持久化生活变化流。事件开始、每个中间阶段、结束即时记录；不依赖心情开关或候选配额。独处感受可作为带来源的临时上下文提供给 DSH、QQ 与 Pet；审核后的自身记忆复用原写回队列，标注 character-life，与青枔事实分开。独处新感受使用单独编号提交给鱼的心情，防重复记账；内部通知不进入青枔真实来信分类。独处插件独立安装并可单独暂停。


### 1.18.0 独处来源与共享接口

生活变化附带反应与心情计分回执；真实聊天改为近期 8 条、2 小时快照并记录活跃表面，不逐条写入待感知变化流。独处记忆使用 character-life 来源，人物演化排除；新感受按原事件去重并受每日独立累计上限约束。与独处生活 0.3.0 配套使用。


### 1.18.1 共同安装登记与独立新感受

心情联动和独处隔离在显式安装时校验彼此协议并同步最终源码摘要，不再互相报告失效；日常候选接纳/配额拒绝状态和心情贡献回执随事件提供给独处审核。原事件影响和反思带来的新感受分开，独处不能替被日常配额挡掉的事件补分，也不会阻止原事件后续阶段计分。


### 1.18.2 升级恢复与跨日配额

另一套适配丢失或协议不兼容时，安装只跳过其登记更新并报告待修复，允许当前安装完成。旧登记保留，健康检查继续报告缺失；另一脚本修复后再同步最终摘要。两种恢复顺序均有“旧登记仍在、上游源码已移除两套补丁”的回归测试。

日常配额拒绝仅阻止该次阶段的候选，不永久封锁整个事件。后续阶段和结束重新按它们实际发生日期的配额判断；成功接纳后才恢复独处新感受资格，仍不能绕过日常配额补计原先被拒的阶段。


### 1.19.0 高关注项目研究后的生活意向与可恢复生成

参考 [Generative Agents](https://github.com/joonspk-research/generative_agents) 的规划分层、[AIRI](https://github.com/moeru-ai/airi) 的观察/动作边界、[AI Town](https://github.com/a16z-infra/ai-town) 的状态代次，以及 [LangGraph](https://github.com/langchain-ai/langgraph) 的检查点设计，新增可调整的生活意向与内容生成草稿恢复。完整来源、核对日期、维护状态及落地说明见 [调研与实现记录](docs/life-research.md)。

Gemini 在原有生活内容生成中同时提出 0–6 条生活意向，自己决定时间窗口、有效期和事件倾向；不会为意向另加模型请求。总览展示意向及实际事件关联。有效意向可以降低、提高或暂缓相关事件的自动抽取权重，仍保留原有时间、冷却和配额；用户手动操作优先。意向是尚未执行的打算，本身不产生心情分数、记忆事实或主动分享。

内容生成在本地应用前保存检查点。中断后复用有效草稿，保留原生成时间，过期或模型/人物等相关设定改变时丢弃；不会仅因修改事件配额而重跑模型。人物补充的部分应用也可恢复且不延长原期限。生活意向可在设置中关闭。


### 1.20.0 意向与独处双向联动及提及冷却

独处生活 0.4.0 可以按编号提出调低、调高或取消意向，经 Gemini 审核后由本插件逐项检查版本、批次、期限及事件关联。回执可重放，重试不重复改动；修改不延长原期限、不改变模板或已经发生的事件，不额外计心情分数。当前有效的已调整意向会保留到原期限，后续每日生成或正在执行的旧生成结果不能恢复重叠的旧安排；新安排也会参考当前独处记录。

意向带 mayMention 与 lastMentionAt，DSH 和 QQ 发送记录沿用现有提及检测，按意向文本、模板名及别名识别。默认三小时内不主动重提，用户追问仍可回应；刷新同一意向不会清空冷却。该机制不增加新的模型调用，不承诺识别所有未使用别名的改写。设置页显示取消、独处调整原因和近期提及状态。


### 1.21.0 人物演化独立审核与实际意向权重

每日生活生成可参考独处记录，但不再生成人物补充或撤销人物事实；兼容旧返回时也忽略这两个字段。人物演化使用独立提炼请求，只输入选中的真实记忆和人物称呼，再通过独立审核核对完整结论的主体、条件、否定和细节。审核必须提供引用证据中的原文并达到90置信度；真实编号本身不等于结论成立。不支持或不确定的新补充不采用；旧补充可保留在本地供检查，但审核不通过时暂停注入。原证据快照及有效期保留，未召回不会删除补充，明确删除的证据不能在重试时复活。

人物审核的提炼、分批审核、应用各自保存检查点；失败保留已完成批次，不重新提炼。证据或待审核补充变化后，自动审核至少间隔1小时，默认每日最多6批，可配置；审核失败按15分钟、1小时、6小时退避，配置错误暂停自动重试。设置页提供独立状态与“审核人物补充 / 重试”，手动操作可立即发起。每批包括一次提炼及按每12项一组的独立审核，另沿用既有记忆选择调用；没有证据不提炼，没有变化不额外调用。接口 POST /persona/update 受与其他修改接口相同的认证和 CSRF 保护。

多条有效意向对应同一事件时，非零权重取平均；0代表明确暂缓或取消，仍优先阻止抽取。例如1和1中一条调到2后，实际乘数变成1.5。回执同时给出每个模板的调整前后乘数、适用时间与阻止它的意向编号。若实际乘数没变，明确显示“仍被暂缓意向阻止”或“合并后未改变”，不会只报已调高。独处生活0.4.1的页面展示这些实际结果，模型上下文也读取同一回执。


### 1.22.0 人物审核触发、语义去重与有效容量

人物演化的自动触发摘要只包含指定记忆文件的有效条目，不包含每轮运行时召回，也不因话题、记忆顺序或召回时间戳变化而重跑。首次升级、相关设置变化和未审核的人物编辑仍会检查；同一份文件内容未变化则不调用记忆选择、提炼或审核。真实文件变化仍受至少1小时间隔、每日批次上限约束。手动审核可立即执行；失败检查点继续按原退避恢复。运行时召回仍可在已触发的审核中提供真实证据，但它本身不触发审核。

提炼收到已有补充的编号与原文作为去重参照，不能把这些文字当证据。表达相同事实时须填写existingId，程序复用原编号、类型和措辞，不延长期限。独立审核仍只凭引用的真实记忆判断结论，同时识别新旧条目间的同义改写；仅双方均通过证据审核才合并，保留原条目、证据快照及较早的有效期限。相关但不同、主体或条件不同、明确否定的事实不应当作重复。

32条限制只用于有效补充。审核未通过的旧条目、合并掉的重复条目以及超额旧条目进入persona-learning.json的独立归档（最多128条），不再注入或占有效名额。容量满时按事实最初创建时间优先保留更新的已审核条目，重复提炼不会刷新创建时间。设置页显示有效数量、归档数量、最近审核进度，并可展开查看归档文字与原因。升级后的第一次独立审核也会整理既有条目。


### 1.22.1 稳定人物补充免重审与两次复核

已通过且supportReview.key与当前证据快照factKey一致、没有待复核标记的补充，直接复用通过结果。它们仍作为语义去重的参照，但不会放进审核候选。重复提炼同一编号也不会重审原条目或延长期限。审核批次在排除缓存后重新分组，因此32条稳定补充加1条新补充只需审核1条。

提炼可依据真实记忆中的明确新否定提出challenges，只有有效既有编号与真实证据编号才进入独立审核。独立审核确认明确否定且有逐字证据、置信度至少90时才立即归档。已通过补充在证据变化或被提出复核后，首次unsupported/uncertain仍保留通过状态及注入，同时记为待复核；连续第二个独立批次仍未通过才归档。成功复核清空失败次数，网络错误不计失败；检查点重试复用同一结果，不把同一批算成两次。待复核项沿用至少1小时及每日批次限制，原到期时间、证据明确删除与容量策略继续生效。

设置页显示本批实际审核数、复用数及待复核条目。缓存结果不是新增模型判断，也不会刷新原审核时间。


### 1.22.2 复核时带上新提炼证据

未通过缓存的既有补充（待复核、升级前未审核或被提出否定复核）若在本批提炼中被沿用编号重新找到，提炼时引用的真实记忆会作为新增证据一起交给独立审核。审核通过后才把这些证据并入该补充的证据快照，并在复核状态中记录新增编号；创建时间与原到期时间不变。审核未通过时不并入，原证据快照保持不变。已通过且证据未变化的稳定补充继续直接复用，提炼到的新证据不会触发重审或改动其快照。已明确删除的证据不会被并入。
