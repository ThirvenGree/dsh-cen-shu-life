# dsh-cen-shu-life

岑舒的独立生活插件。按《岑舒_第七版》维护日程、轻量随机事件与心情行为，不修改 DSH 核心，不自己发送消息。

## 安装

需要 Node 22+ 和 DSH Desktop。当前实测 DSH 0.2.1-rc.3、dsh-feiyu-mood 0.7.6、dsh-speak-up 0.2.6。

```powershell
git clone https://github.com/ThirvenGree/dsh-cen-shu-life.git
cd dsh-cen-shu-life
node scripts/install.mjs "你的DSH家目录/profiles/desktop" "你的岑舒会话ID"
```

重启 DSH。设置侧栏打开「岑舒生活」，设置目标会话与心情记录键。修改设置立即生效；安装、更新宿主代码需重启。默认不绑定任何会话，其他角色不受影响。`DSH_HOME` 优先，否则使用用户家目录下 `.dsh`。

## 职责

- `dsh-feiyu-mood`：判断、保存和衰减心情。
- `dsh-speak-up` / 现有 QQ bridge：继续各自触发主动聊天。
- 本插件：日程、事件、行为映射、上下文，不调用模型做心情判断、不直接发送。

实际安装版本的 `/dsh-feiyu-mood/state` 调用会执行 `getState(... persist:true)`，不是无副作用的跨插件读取。因此采用只读 v2 文件适配器；验证版本、七维数值与明确会话绑定，读取失败保持平常并记日志。文件更新异常不会写回原心情。不读取或覆盖整份聊天历史。

## 插件内设定与工具联动（1.1）

人物背景、一般说话方式、关系边界、每周倾向及工具协作规则保存在本地 `profile.json`；11 种模式的表达规则保存在 `config.json.modeRules`。首次使用的默认规则来自 `data/behaviors.json`，不是测试消息中的长提示词。DSH 设置 → 岑舒生活，可在现代化面板中直接编辑并保存，下一轮立即读取。原始角色卡保持只读。

`censhu_life_context` 是绑定角色专用的状态读取工具；每轮也通过动态上下文自动读取，不依赖模型记得调用。工具仍按已有配置工作：BrowserSkill 路由、文件/图片/表情预览、语音、生图和记忆不会被生活模式禁用。心情只调表达，明确任务仍需完整完成。API 密钥仍在原环境变量中，不复制到本插件。

测试会话通过 `/simulate/session` 临时挂载隔离的模拟上下文，聊天里只传真实测试发言，不贴整段角色设定。模拟绑定只存内存，20 分钟过期，禁止覆盖正式角色会话，可主动清除。

## 生活事件 → 真实心情（1.2）

本机已安装原心情插件适配。重新安装到兼容部署时运行：

```sh
node scripts/install-mood-link.mjs /path/to/dsh-feiyu-mood
```

安装器针对本部署已适配的 feiyu-mood 0.7.6 检查源码锚点、保留备份，再接入原有轮末判断。未知版本会在写入前拒绝；不修改 DSH 核心，不手动改原心情文件。

事件开始、阶段推进和自然结束时，从 `mood-reactions.json` 按人物兴趣与事件类型抽取一次轻微反应，保存在 `mood-events.json`。默认 65% 进入加权反应抽样，抽样里仍包含平常反应；强度 1，每天最多 4 个候选，24 小时过期。同一候选刷新、重启不重抽；概率/强度只影响以后产生的候选，关闭联动会暂停所有待处理输入。

原 feiyu-mood 下一次正常轮末判断同时处理新对话与未处理事件，仍只调用一次判断模型；把生活贡献单独列出，允许为 0。每次生活原始贡献限制为总心情 -3..3、单维 -6..6，并沿用原心情总分缓慢变化机制。生活事件不能生成甜蜜、吃醋、心疼或担心青枔等关系情绪。采样为中性时数值贡献强制为 0。

原心情插件自己保存数值、历史和事件回执；生活插件仅重读。重复事件、过期事件、重置前事件不会再次加分，也不允许因角色复述事件或旧心情造成的口吻持续自增。事件发生时没有聊天，不单独唤醒模型；等下一次正常判断更新真实数值。

新心情会在下一次符合条件的请求转成当前表达模式。当前模式优先于常态篇幅：低落不会因为普通设定写着三五句而继续连问。青枔明确需要关心、认真问感情等情境优先，明确任务和工具执行不因心情被省略。

设置页面新增生活情绪开关、反应概率、强度、每日上限、有效期和待处理状态。独立的模型联动模拟调用原心情插件的判断与数值应用函数，但只更新内存模拟对象，不写真实心情，不发 QQ。

```sh
node scripts/check-installed-mood.mjs /path/to/dsh-feiyu-mood
```

这是可选本机集成检查，不参与无外部插件的 CI。适配源码备份为 `lib/index.js.before-life-link.bak`；解除适配时先关闭生活情绪开关，在确认心情插件未另行升级后恢复该备份。保留原心情数据与角色卡。

## 功能

- 上海时区日程，可修改；工作日与周末分开，春节按农历判断。
- 17 个 JSON 事件模板：档案工作、旧书、纪录片、整理、感冒、修路、家庭电话、天气、季节、工资及出行。每个模板含条件、权重、阶段、持续时间、冷却与重复限制。
- 默认每 30 分钟一次随机检查，概率 0.22，每日最多 2 件、同时最多 2 件；可以没有新事。离线不补造大量事件，重启只推进已存在事件。
- 天气必须手动确认有效期；工资日未配置不触发；出行默认关闭。不会自动查询现实天气、工资或出行。
- 11 种行为：平常、有点高兴、很高兴、低落、心软、难为情、吃醋后收声、累、烦、被惹到、慌。综合可信心情、基线差、七维变化、日程与真实新消息；低分不等于烦，甜蜜不自动等于难为情。
- 关心优先、感情场景优先、最短维持、恢复过渡与最长有效期。阈值、持续时间、各模式具体规则可配置。
- 每轮重新读取有效心情，使用 DSH `systemPrompt.context`，只注入绑定会话。心情判断在轮末完成，下一次模型请求使用新结果，不回写已生成回复。
- QQ 初始快照及等消息工具返回的新消息参与场景判断；成功发送及 DSH 正文参与提及记录，避免连轮重复。
- 设置页支持开关、绑定、时区、数量、概率、分类、阈值、行为文本、状态预览、手动新增/结束/重置、完全隔离的模拟测试。

事件属于角色生活模拟，不是用户现实经历。日程只是倾向；未记录的书名、影片结局、电话细节不当事实。事实约束不能保证模型每次生成都完全遵守，因此提供实际回复验收与样例。

## 本地文件

`<DSH_HOME>/cen-shu-life/` 下保存 `config.json`、`profile.json`、`events.json`、`state.json`、`history.json`、`diag.log`。JSON 均有版本号，原子替换；损坏配置保留备份，恢复默认且不自动绑定。日志有大小上限，历史有数量上限。原始人物卡和心情文件始终只读。

`modeRules` 为模式键到行为文字的 JSON 映射（如 `{"low":"回复变短……"}`），空对象使用默认规则。天气可通过配置接口设置 `weather: {kind:"rain", expiresAt:毫秒时间戳}`；也支持 `humid/hot/cold`。天气信息不自动更新。

## 接口

接口挂载在同一 DSH 本地回环服务。实测当前版本的插件路由可在本机直接访问，不要求 DSH 会话 Cookie；修改接口检查同源，返回内容不包含密钥或聊天令牌。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/dsh-cen-shu-life/settings` | 独立设置页面 |
| GET | `/dsh-cen-shu-life/state` | 状态、心情读取结果、上下文与模板 |
| GET/POST | `/dsh-cen-shu-life/config` | 读取/保存设置 |
| GET/POST | `/dsh-cen-shu-life/profile` | 读取/保存人物与工具联动设定 |
| POST | `/dsh-cen-shu-life/simulate/session` | 独立测试会话的临时模拟绑定/清除 |
| POST | `/dsh-cen-shu-life/event` | `{action:"add",templateId}`、`{action:"end",id}`、`{action:"reset"}` |
| POST | `/dsh-cen-shu-life/simulate` | 独立心情、场景、日程与事件模拟，不修改真实状态 |
| POST | `/dsh-cen-shu-life/simulate/judge` | 调用原心情判断处理模拟事件，返回模拟数值和后续模式 |

卸载时从 profile 的 dependencies、bundles 移除本插件并重启；自己的数据可保留，永不删除原始角色卡或心情数据。恢复安装可复用旧事件。

## 1.3：语义判断、升级与内容更新

- 默认数据采用三方合并：未修改的默认字段随版本更新，手动改动和删除保留；首次启动不再永久冻结默认值。
- `GET /state` 仅预览，不推进事件、抽随机数或写入状态。事件推进由定时器与实际会话执行。
- 心情联动采用协议 2 和源码摘要校验。升级覆盖适配会在设置页显示故障；修复按钮可重新安装已支持适配，随后重启 DSH。不兼容的新版本会明确报错，不能保证任意未来版本自动兼容。
- Google `gemini-3.8-flash` 输出固定结构的情境标记，判断表白、需要照顾、恢复等语义；不再解析自由文本 reason。默认从本地环境变量 `GEMINI_API_KEY` 读取凭据，不写入插件配置。支持本机 HTTP 代理、会话隔离缓存、超时与可见降级。原心情插件仍是心情数值的唯一写入者。
- 默认每 24 小时更新生活事件、日程倾向与心情表达细节。生成数据经过类型和范围校验，单独保存在 `model-content.json`，不修改程序代码、人设原稿或手动规则。失败保留上次有效内容，6 小时后重试；生成层 7 天过期。设置页可关闭或手动刷新。
- 内容请求只携带人物与行为配置、已有模板名称，不携带 QQ 聊天记录。语义分类仅发送当前消息正文。调用使用已有 Google 账户额度。

验证：`npm ci`、`npm test`、`npm run check`；原生联动检查 `node scripts/check-installed-mood.mjs <心情插件目录>`。真实模型回归（需要本地 key）：`node scripts/check-google-situation.mjs [本机代理地址]`。


## 1.4：日历、可信情境与请求边界

2026 年日程按官方放假与调休日期区分工作、休息、早晚活动。工作事件使用同一工作日判定。日历来源：[国务院办公厅通知](https://www.gov.cn/zhengce/content/202511/content_7047090.htm)。未覆盖年份仅提供基础节日识别，不声称知道尚未收录的完整调休安排。

每条消息在收到时发起一次 Gemini 分类，生成回复及读取上下文工具等待同一任务；上下文只在组装时计算一次，读取不推进事件或写盘。失败、超时和低于 70 的结果均为未知，不使用正则制造可信状态。连续失败三次熔断一分钟；key 优先读取进程环境，注册表查询为异步并缓存五分钟。

协议 3 要求情境携带模型来源与时间。1.4.1 起，分类中、未知和普通回应保留仍有效的旧证据；只有可信且明确的恢复/撤回标记会立即解除对应模式。事件反应在开始时固定，各阶段不重抽；配额与心情联动开关只控制提交，不改变该事件自身的抽样与行为。原心情插件成功处理一批事件后即记已处理，即使低置信度、未采纳或零变化，也不反复提交。请求失败未得到判断时仍可重试。

所有设置路由校验本机 Host、端口、来源与连接地址。修改请求还需先从受保护的 `GET /state` 获取本进程 `csrfToken`，以 `x-censhu-csrf` 请求头发送；昂贵操作有十秒限频。Token 不写入配置或 URL，DSH 本身的会话鉴权继续生效。


## 1.4.1：跨回合情境连续性

“本句没有提到难受”不等于“已经恢复”。待分类、未知、关闭语义辅助、普通回应或回合结束，不撤销可信旧证据，也不跳过最短维持和恢复阶段。`behaviorContext` 的需要关心、撩拨、第三方感情证据重新参与心情行为联动。`soft` 仅被明确且可信的 `careResolved` 立即解除；Gemini 同时参考上一份有效情境与此前模式；其他情境型模式使用模型输出的 `resolvedModes` 标注明确撤回/澄清，普通的“嗯”“好”和话题切换不构成解除。

每项正向证据、每项解除标记都有独立时间戳；普通回应不续期旧证据。证据自然过期后采用原有维持与恢复逻辑。未知结果不会写成可信情境，也不会覆盖最后有效情境。事件自身反应始终独立抽样、跨阶段固定；`moodLinked` / `lifeMoodEnabled` 关闭时，“烦”等行为依然可触发，只是不提交心情影响。


## 1.5：开放、动态的主观判断

Gemini 参考人物摘要、既有可信情境、先前开放判断、心情维度与已发生的生活事件，输出自由命名的感受、理解、说话倾向和行为建议。开放标签不受 11 种基础模式限制，允许混合感受、不确定和困惑。基础模式继续执行已配置的关心优先、最短维持与恢复规则；开放判断在这些底线内细化表达。

判断采用 preserve/update/resolve 三种内部操作协议控制延续，情绪名称和表达内容由模型生成。不确定的模型结果可以作为未定性的表达背景保留，但不能解除旧关心、制造表白证据或改写心情数值；网络错误不扮作角色困惑。当前开放判断会保存在本地、在“模拟与预览”中展示，并随有效期过期。模型仍只更新内容与建议，不修改程序、权限、人物核心或直接执行发送。


## 1.5.1：缓存、情境寿命与人物口吻边界

`semanticCacheMinutes` 仅决定 Google 分类 API 结果的复用时长（默认 15 分钟）。独立的 `situationValidityMinutes` 决定情境证据、解除标记和开放判断的寿命及 preserve 窗口（默认 120 分钟，1–1440 可调）。普通回应不续期各项旧证据，原有最短维持、恢复过渡仍独立执行。

Gemini 关闭、不可用、超时或熔断时，仅启用整句明确困难的关心兜底，例如“今天好难受”。兜底来源单独标记、置信度不补高，不持久化成可信模型证据；不会推断表白、冒犯或恋爱。“我已经不难受了”“我朋友今天好累”和引用台词不触发。

开放判断自由文本、每日内容层中的日程备注及口吻/行为建议仅保存并展示，不再注入角色系统提示，也不回传给下一轮分类。分类只接收之前的结构化情境和确定程度；主聊天模型依据原人设自行选择语气；生成的生活事件仍作为经过校验的候选，在真正开始后进入生活记录。模型产生的动态标签仍可在设置页查看，不确定/困惑通过受控的状态提示保留。先前 1.5 关于开放文本影响表达的描述由本节替代。


## 1.6：模型建议时长与临时内容注入

情境按类型分别计时。Gemini 通过 `durationMinutes` 建议各项保留时间；程序将建议限制在设置的类型上限与总上限内。默认关心/恢复标记上限 120 分钟，撩拨、第三方感情、表白 20 分钟，冒犯 30 分钟；旧记录没有时长时采用这些类型默认值。每项保存独立起点和到期时间，普通回应不能续期。短期难为情/吃醋/慌的维持与恢复各最多 5 分钟，避免情境到期后再额外恢复半小时；心情维度仍决定有效情境能否触发。

按用户最新要求，恢复开放判断四项自由文本（感受、理解、说话方式、行为建议）注入，每项最多 200 字。`assessmentMinutes` 由模型建议、总上限约束；记录固定到期时间，preserve 不续期。人物核心、手动规则、明确任务和工具权限始终优先。此节替代 1.5.1 的“仅展示”策略。

每日更新的日程备注与行为建议通过每条 `validMinutes` 提出时长，按日程时段和当前模式筛选后作为临时内容注入。日程备注可从当天对应时段开始计时；所有备注最迟在本批生成后 24 小时内退出。候选生活事件仍有独立的七天候选有效期。到期不会改写人物原稿。


## 1.6.1：未来时段与首次模式激活

日程备注按配置时区定位生成后 24 小时内对应时段的下一次出现；已过时段安排到次日。正在该时段内则从生成时刻起计时，开始前则从该时段开始，结束不超过时段末尾及整批截止。秒数不会把窗口错移到下一分钟，跨日和跨年也按当地日期处理。

行为备注生成后处于待用状态，在后台或聊天正式评估首次提交匹配模式时开始计算模型建议时长。离开再回到该模式不会续期，激活时刻和到期时间持久化，重启也不续期。状态读取、上下文预览均不激活或写盘。所有备注最多保留到该批生成后 24 小时；临近截止才触发也只获得剩余时间。

旧的仍有效批次会迁移到新时段规则：使用原始生成时刻和原批次截止重算，不从升级时刻重新获得 24 小时。尚无首次模式激活记录的旧行为备注转换为待用；新格式后续重启不再重置。候选事件与四项开放自由文本的有效期机制保持原样。


## 1.7：大理每日联网天气与主动机会

地点固定为云南省大理白族自治州大理市。默认北京时间每日 07:00 后查询一次；程序晚启动则当日补查，需 DSH 运行。使用现有 Gemini 模型、环境变量 key 和代理，先调用 Google Search 获取搜索证据，再结构化提取预报。拒绝没有真实搜索来源、地点/日期不符或非法温度的结果，不以月均气候替代当日预报。设置页显示来源、查询时间并支持手动刷新。预报在大理当地午夜过期；失败保留仍有效的上次结果，一小时后重试。搜索与提取会使用 Google 搜索/API 额度。参考：[Google Search Grounding](https://ai.google.dev/gemini-api/docs/generate-content/google-search)。

天气预报作为临时背景进入人物上下文，可温和影响表达；不会当成窗外实况或青枔当前位置。每天最多一条天气心情候选，建议总分不超过 ±3、happy/calm/sad 不超过 ±4，仍由原心情插件本轮正常判断采纳与写入，不额外定时修改心情。天气候选有独立每日一次额度，日常小事配额不受占用。不会仅凭降雨预报自动声称已下雨或已淋雨。

运行 `node scripts/install-weather-policy.mjs <dsh-censhu-policy目录>` 接入 bridge 与 dsh-speak-up 的共享主动策略。两套现有主动检查都可考虑天气话题，未处理的当日天气机会给予温和概率修正；仍保留原时段/心情/概率门槛、60分钟共享冷却与互斥锁，同日天气机会共享去重。机会被处理不等于消息已发送，模型仍可选择不说；也不会强制两套同时发送。四个天气开关及查询小时可在设置页修改。


## 1.7.1：天气独立额度与主动策略健康检测

日常候选额度统计排除具有完整天气标识的候选。天气仍在同一心情队列中，每天最多一条；默认可同时有天气一条及日常小事四条，共五条。每轮仍最多取两条，后续正常心情判断继续消费余下候选，不必增加单轮模型负担；模型仍可判断为零变化。天气先到、后到、日常额度已满或为零都不占用日常额度。

天气主动辅助层增加协议 1、源码 SHA-256、目标包及依赖校验，安装记录写在本地 `weather-policy-install.json`。检测到重装、适配缺失或摘要改变时，天气概率修正和主动话题暂停，普通主动策略及天气查询/心情功能不因此关闭。设置页显示单独故障横幅；兼容版本可点击“检查并重新接入天气主动策略”，成功后需重启 DSH 与 bridge。修复接口使用既有本机 Host/来源/CSRF 校验及限频。未知不兼容源码明确报错，不保证任意未来版本均可自动修复。


### 1.8 动态内容与已有记忆联动

- 模型依据人设、当前时间/季节、心情、天气预报、近期事件和指定 DSH 记忆生成候选事件与情绪反应。每批最多12个，不要求凑数；滚动事件池最多80条，各自7天到期，重复不续命。内置模板继续作为基础。
- 事件附带模型生成的轻微反应供随机采样；同一事件只抽一次，阶段不重抽。关闭心情数值联动仍保留行为反应；原心情插件继续独占数值写入。
- 每轮开放判断、每日临时表达与手动模式倾向共同参考，允许主模型自然选择、混合或不用，不是固定台词。
- `personaMemoryFiles` 选择 DSH `memories/` 下的相对 Markdown 文件，接入已安装记忆插件维护的项目 MEMORY.md、KEY.md 等。只读选定文件，不扫描其他项目、不修改记忆插件，也不写 Codex 记忆。当前模型仅提炼提及岑舒/青枔的记忆段落。
- 人物更新存于 profile.json 的 evolvingFacts：经历、偏好、关系细节，必须引用本批真实记忆证据且置信度至少90；模型决定1至90天有效期，相同内容不自动续期。不确定时不写事实。人物核心、边界、权限与手动规则优先，模型无法改写这些字段。
- 仍由原有记忆功能记录与整理对话；生活插件读取其结果。每分钟检查选定记忆，变化距上次成功生成满1小时后可提前刷新；失败仍退避6小时。设置页可关闭联动、编辑/清空人物补充，自动更新保留最近10次人物修订于 persona-history.json。
- 生活总览增加大理当日天气卡片，展示有效预报、温度、日期和更新时间；到期不展示昨日天气，来源在模拟与预览页。

已安装的 dsh-memory-evolve（memory:snapshot）、Mnemon、OpenViking 在绑定会话提供的命名记忆上下文也会自动接入，按会话隔离、7天上限，原插件继续负责召回和存储。只读取命名记忆上下文里涉及角色/青枔的短段落，不把整段普通用户提示当记忆。

`censhu_memory_review` 向所有 DSH 会话提供 Gemini 记忆质量审核工具：保留、压缩、待核实、过滤，逐条返回原始 id 和理由。审核本身不改存储；主 DSH 使用其已有 memory、Mnemon、OpenViking 等工具执行写回和归档，因此仍保留原插件的来源、范围和恢复机制。

生活总览展示鱼的心情的总值和7个维度、最近生活贡献与本轮实际变化（包含同轮对话贡献，不误标为纯生活贡献）。生活候选经原插件正常回合统一判断、去重、写入其真实state；允许判定无变化，不伪造涨跌。反向读取原插件数值决定当前模式/表达，内容生成也携带数值；显著变化且距上次成功生成满1小时可提前刷新内容，不每次读页面调用模型。

### 1.8.1 内容容错、证据留存与双向反馈

- 每日内容逐个校验事件、日程、表达和人物补充；不合格单项及重复项丢弃，合法同批内容照常采用。设置页显示采纳/过滤数量；不支持的根版本、网络失败仍保留上一份内容。
- 人物补充保存证据原文、来源、原始有效期；本次没召回、召回截断、来源暂时不可用不删除补充。新内容不能挤掉有效旧补充。旧格式在再次召回相同证据时补存原文，未补齐时仍保留到原有效期。明确成功的原记忆 remove 操作撤销匹配证据；多个独立证据仍有效时保留补充。Gemini 可根据当前明确否定证据提出 factRevocations，须引用当前有效证据且置信度至少90，撤销与到期不同于召回缺失。
- 生活总览数值与鱼的心情一致取整展示，底层数值精度保留；中文显示各维变化，区分生活判定量与同轮实际变化（含对话且经过原心情插件折算）。
- 原心情时间线保存生活事件名、判定量、实际变化。鱼的心情设置及挂件增加「受到的影响 / 产生的影响」列；生活总览也有这两列，展示真实队列、判断记录和读取确认。候选未判断不会显示成已生效，行为反馈不等于发过消息。
- 生活插件每3秒检查数值修订，变化后重新评估行为并保存读取确认；普通页面读取仍无副作用。模型事件池、临时心情表达及显著变化触发内容刷新继续运行，页面标示模型动态内容和下次更新时间。
- `install-mood-link.mjs` 同时安装原心情接口及两个展示入口的反馈适配；可重复运行，原生文件先备份。

### 1.8.2 记忆条目边界与动态表达状态

记忆文件及已安装插件的记忆上下文共用条目解析：支持不空行的 Markdown 列表、编号列表、带日期条目、§分隔以及缩进续行；超长单条拆成不超过1200字的片段，各片段记录共同的原条目标识。证据ID不依赖相邻条目与列表编号。删除仅按完整条目标识/规范化全文匹配，不再用子串使整段失效；旧版整段引用不因删除其中一条就被全部撤销。旧格式缺少精确条目归属时保留到原有效期或交给有新证据的模型复核，不猜测其所属。

「心情与表达」页直接显示模型动态表达开关、最近生成/下次检查时间、未到期的每日表达建议及等待/当前有效状态、本轮开放判断；基础模式仍可编辑，模型表达不是固定台词。

### 1.9 每4小时的 Gemini 随机生活事件

首次安装后默认4小时第一次，之后每4小时一次；重启沿用保存的下次时间，错过多个时段只补一件，不集中补发。`timedEventsEnabled` 可开关，`timedEventHours` 默认4，可在设置调整。生活事件页显示下一次发生、最近事件和失败原因。网络/校验失败15分钟后重试，禁用或卸载后的迟到结果不提交。

Gemini 结合人物、时间/休假、当前心情、天气预报、记忆和近期事件，加随机盐动态创作一件普通生活小事，并在同一次调用给出轻微情绪判断和自由表达倾向。事件独立于日常概率抽选及其每日配额，保留一个定时事件名额；单件持续15–180分钟，不因原有每日上限被丢掉。仍不冒充用户经历，不新增未确认的外部事实。

事件及Gemini情绪结果入持久队列，原鱼的心情在自身串行写入队列中每3秒检查，不需要对话回合，也不再调用第二个模型。数值由原插件应用折算/上下限并保存到原state，生活贡献仍限制总值±3、开心/踏实/难过各±6，允许部分或全部不变；不强制造成恋爱维度。普通对话路径不再重复处理定时条目，重启未消费条目可继续消费，重置/禁用/改绑闸门保持有效。阶段结束不重复入队，同一记录只处理一次。

共享岑舒心情经现有联动影响生活行为、临时表达和两套主动聊天的判断。随机事件本身不发消息、不绕过作息或共享冷却。

### 1.9.1 最近证据优先与持久计时

文件记忆从新到旧选择：带明确日期的条目按日期降序，其余按文件末尾优先；跨文件先比较日期，再比较文件更新时间。证据ID仍与读取排序无关。文件独享最多32条/8000字，运行时召回独享最多16条/4000字，二者互不挤占；撤销及重复证据在选取前过滤。

重启保留原bootAt、nextAt及失败重试截止。未来的截止不延后；已错过的截止在启动后检查时只触发一次，随后跳至原节奏的下一个未来时段，不逐个追补。只有无有效存档时从当前时间加4小时开始，关闭期间不调用模型，重新开启仍按已有截止处理。

### 1.9.2 每个记忆文件保底

文件证据先按来源分组，每个有有效证据的文件先取最多3条（各自仍按日期/末尾优先，并受公平分配的字数约束），再把32条总名额中的剩余名额按全局新旧补齐。文件缺失、全被撤销或不足保底时不占空名额。通常字数预算仍为8000；为保证最多8个文件各自至少能容纳一条最长1200字证据，必要时上限扩至9600字。运行时召回仍使用独立16条/4000字。KEY.md 不再因其他文件拥有大量带日期的条目而完全不可见。
